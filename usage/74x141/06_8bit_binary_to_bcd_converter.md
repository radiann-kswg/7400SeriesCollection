# 74x141 を使った 8 ビットバイナリ →BCD→ ニキシー管表示回路（Double-Dabble アルゴリズム実装）

## 回路概要

8 ビット 2 進数（0 ～ 255）を入力として受け取り、Double-Dabble アルゴリズムによる変換回路を経てニキシー管で 10 進数表示する回路です。3 桁のニキシー管を使用し、0 ～ 255 を「000」～「255」として表示します。シフトレジスタと加算器を組み合わせた反復アルゴリズムをハードウェアで実現します。

**注意**: この回路は 4 ビット版（[03_binary_to_bcd_converter.md](./03_binary_to_bcd_converter.md)）の発展版です。基本的な概念を理解してから取り組むことを推奨します。

## 回路の仕様

- **入力**: 8 ビット 2 進数（00000000 ～ 11111111、0 ～ 255）
- **出力**: 3 桁 10 進数表示（000 ～ 255）
- **変換方式**: Double-Dabble アルゴリズム（Add-3 アルゴリズム）
- **表示方式**: 静的点灯（3 桁独立駆動）
- **変換時間**: 約 8 クロックサイクル（反復処理）

## Double-Dabble アルゴリズムの原理

### アルゴリズムの概要

Double-Dabble（または Shift-and-Add-3）は、バイナリを BCD に変換する代表的なアルゴリズムです：

1. **初期状態**: BCD レジスタ（各桁 4 ビット）とバイナリレジスタを用意
2. **反復処理**（バイナリビット数分繰り返し）:
   - 各 BCD 桁が 5 以上なら、その桁に+3 を加算
   - 全体を 1 ビット左シフト（バイナリ →BCD 方向）
3. **終了**: シフト完了後、BCD レジスタに変換結果が格納

### 8 ビット変換の具体例（10 進数 83）

```
初期状態:
  BCD百の位: 0000
  BCD十の位: 0000
  BCD一の位: 0000
  バイナリ: 01010011 (83)

反復1回目:
  - チェック: 全桁<5、加算不要
  - 左シフト: 0000 0000 0000 1010011

反復2回目:
  - チェック: 全桁<5、加算不要
  - 左シフト: 0000 0000 0001 010011

反復3回目:
  - チェック: 全桁<5、加算不要
  - 左シフト: 0000 0000 0010 10011

反復4回目:
  - チェック: 一の位=5、+3 → 1000
  - 左シフト: 0000 0000 0101 0011

反復5回目:
  - チェック: 一の位=5、+3 → 1000
  - 左シフト: 0000 0001 0000 011

反復6回目:
  - チェック: 全桁<5、加算不要
  - 左シフト: 0000 0010 0000 11

反復7回目:
  - チェック: 全桁<5、加算不要
  - 左シフト: 0000 0100 0001 1

反復8回目:
  - チェック: 全桁<5、加算不要
  - 左シフト: 0000 1000 0011

結果:
  百の位: 0000 (0)
  十の位: 1000 (8)
  一の位: 0011 (3)
  → 表示「083」
```

## ピンアサインと配線方法

### 全体構成ブロック図

```
[8ビット入力] → [74x165 バイナリシフトレジスタ]
                         ↓ (シリアルシフト)
                         ↓
    [クロック] → [制御回路(74x163カウンタ + 74x74制御FF)]
                         ↓
    [74x164×2 BCDシフトレジスタ] ← (左シフト)
            ↓
    [≧5判定回路] → [+3加算器(74x83×3)]
            ↓
    [74x173ラッチ×3] → [74x141×3] → [ニキシー管×3]
```

### 8 ビットバイナリ入力レジスタ（74x165）

```
        74x165 (8ビットPISO)
        +---v---+
    SH//LD -|1    16|- VCC (+5V)
   CLK -|2    15|- CLK INH
     E -|3    14|- D (入力I0)
     F -|4    13|- C (入力I1)
     G -|5    12|- B (入力I2)
     H -|6    11|- A (入力I3)
  /QH -|7    10|- SER (入力I4からカスケード)
   GND -|8     9|- QH (シリアル出力)
        +-------+

入力I0～I7 → 74x165 A～H (pin 11,12,13,14,3,4,5,6)
QH (pin 9) → BCDシフトレジスタの最下位ビット入力
```

### BCD シフトレジスタ（74x164×2）

12 ビット（3 桁 ×4 ビット）の BCD レジスタを構成:

```
74x164 #1 (一の位 + 十の位下位2ビット):
  CLK (pin 8) ← 共通クロック
  A, B (pin 1, 2) ← シリアル入力（74x165 QH）
  QA～QH (pin 3～6, 10～13) → 一の位BCD + 十の位下位2ビット

74x164 #2 (十の位上位2ビット + 百の位):
  CLK (pin 8) ← 共通クロック
  A, B (pin 1, 2) ← 74x164 #1のQH（カスケード）
  QA～QF (pin 3～6, 10, 11) → 十の位上位2ビット + 百の位BCD
```

### ≧5 判定回路（74x85 の代替実装）

74x85（マグニチュードコンパレータ）が未所持のため、論理ゲートで実装:

**4 ビット BCD 値が 5 以上かを判定する論理式:**

```
GE5 = B3 OR (B2 AND (B1 OR B0))

論理展開:
  B3=1 → 8以上 → 必ず≧5
  B3=0, B2=1, B1=1 → 6 → ≧5
  B3=0, B2=1, B0=1 → 5 → ≧5
  それ以外 → <5
```

**各桁ごとに判定回路を実装:**

```
一の位判定:
  O3 ---|
        |--- 74x32 (OR) --- GE5_O
  O2 ---+--- 74x08 (AND) --|
  O1 ---|    OR
  O0 ---|

十の位判定: (同様)
百の位判定: (同様)
```

### +3 加算回路（74x83×3）

各桁に対して、≧5 の場合のみ+3 を加算:

```
        74x83 (4ビット全加算器)
        +---v---+
    A4 -|1    16|- VCC (+5V)
    B3 -|2    15|- B4
    A3 -|3    14|- C4 (キャリー出力、未使用)
    B2 -|4    13|- C0 (キャリー入力 = GND)
    A2 -|5    12|- GND
    B1 -|6    11|- B4
    A1 -|7    10|- Σ1 (結果ビット0)
    Σ4 -|8     9|- A4
        +-------+

一の位用74x83:
  A1～A4 (pin 7,5,3,1) ← 一の位BCD (O0～O3)
  B1～B4 (pin 6,4,2,15) ← (GE5_O ? "0011" : "0000")
  Σ1～Σ4 → 次段シフトレジスタ入力

74x08でゲート制御:
  GE5_O AND "1" → B1
  GE5_O AND "1" → B2
  GE5_O AND "0" → B3 (常に0)
  GE5_O AND "0" → B4 (常に0)
```

### 制御回路（74x163 カウンタ + 74x74 状態管理）

8 回の反復処理を管理:

```
74x163 (反復カウンタ):
  CLK ← システムクロック
  Q0～Q3 → 現在のカウント値（0～7）
  RC (pin 15) → カウント終了検出（8到達）

74x74 (状態管理FF):
  FF#1: 変換実行中フラグ
    D (pin 2) ← 開始ボタン OR 実行中
    CLK (pin 3) ← システムクロック
    Q (pin 5) → 実行中信号
    /CLR (pin 1) ← 74x163のRC (8到達で終了)

  FF#2: 表示更新フラグ
    D (pin 12) ← 74x163のRC
    CLK (pin 11) ← システムクロック
    Q (pin 9) → ラッチ信号
```

### クロック発振器（NE555）

変換処理の速度を制御:

```
[+5V]
  |
  +---- NE555 pin 8 (VCC)
  |
  +--[1kΩ]--+--[可変抵抗100kΩ]--+
  |         |                    |
  |         +---- NE555 pin 7 (DISCHARGE)
  |         |
  |         +---- NE555 pin 6 (THRESHOLD)
  |         |
  |         +--[0.1μF]-- GND
  |         |
  |         +---- NE555 pin 2 (TRIGGER)
  |
  +---- NE555 pin 4 (RESET, プルアップ)

NE555 pin 3 (OUTPUT) → システムクロック

周波数調整: 10Hz～100Hz程度
  - 速すぎると人間には追えない
  - 遅すぎると変換に時間がかかる
  - 推奨: 約50Hz（変換時間 約160ms）
```

## 配線の注意事項

### シフトレジスタのカスケード接続

- 74x164 を 2 個カスケード接続し、12 ビット（3 桁 BCD）を構成
- クロック信号は全てのシフトレジスタに同期して供給
- シリアルデータの伝播方向を間違えないこと

### 加算器の入力制御

- 74x83 の入力 B は、≧5 判定結果により動的に変化
- 74x08（AND ゲート）で GE5 信号により"0011"または"0000"を生成
- キャリー入力 C0 は必ず GND に接続

### タイミング制約

- クロック周波数が高すぎると、加算回路の伝播遅延が間に合わない
- 推奨最大周波数: 100kHz（CMOS 版 74HC シリーズの場合）
- 本回路では人間が視認できる速度（10 ～ 100Hz）を推奨

### リセットシーケンス

1. リセットボタン押下
2. 全シフトレジスタとカウンタをクリア
3. 74x165 にバイナリ値をパラレルロード
4. 開始ボタンで変換開始

## 動作確認手順

### 初期確認

1. 全 IC の電源配線を確認
2. DIP スイッチを 00000000 に設定
3. クロック発振器の動作確認（オシロスコープ推奨）

### 低速クロックでの動作テスト

1. NE555 を約 1Hz（1 秒周期）に設定
2. DIP スイッチで簡単な値（例: 00001010 = 10）を入力
3. 開始ボタンを押下
4. シフトレジスタの内容が 1 ビットずつ変化することを確認
5. 8 クロック後、ニキシー管に「010」と表示されることを確認

### 高速クロックでの変換テスト

1. NE555 を約 50Hz に設定
2. 様々なバイナリ値で変換テスト:

| 2 進数   | 10 進 | 期待表示 |
| -------- | ----- | -------- |
| 00000000 | 0     | 000      |
| 00001010 | 10    | 010      |
| 01100100 | 100   | 100      |
| 11111111 | 255   | 255      |
| 10000000 | 128   | 128      |

### トラブルシューティング用低速テスト

変換過程を観察するため、クロックを手動（タクトスイッチ）に変更:

```
NE555の代わりに:
[タクトスイッチ] --+-- [74x132 デバウンス] → システムクロック
                   |
                   +-- [0.1μF] --- GND
                   +-- [10kΩ] --- +5V
```

1 クロックずつ手動で進めることで、各段階の状態を確認可能。

## トラブルシューティング

### 変換結果が不正確

- ≧5 判定回路の論理式を再確認
- 74x83 の配線（特に B 入力のゲート制御）を確認
- 各段階で中間値を LED で表示して追跡

### シフトが正しく動作しない

- 74x164、74x165 のクロック信号を確認
- シリアルデータの伝播経路を確認
- カスケード接続の配線を再確認

### 8 回で終了しない

- 74x163 カウンタのリセット条件を確認
- RC 出力（カウント終了検出）の配線を確認

### 表示が更新されない

- 74x173 のラッチ信号タイミングを確認
- 変換終了時にラッチパルスが発生しているか確認

## 回路の拡張性について

### 16 ビット（0 ～ 65535）への拡張

- 74x165 を 2 個に増やす（16 ビット入力）
- 74x164 を 3 個に増やす（20 ビット = 5 桁 BCD）
- 反復回数を 16 回に変更
- ニキシー管を 5 桁に増やす

### 高速化（パイプライン処理）

- 複数の変換回路を並列配置
- 1 つの回路が変換中に、次の回路が別の値を変換
- スループットの向上

### マイコン連携

- 変換結果をシリアル出力（74x165 で読み出し）
- Arduino 等で受信し、ログ記録やグラフ表示
- USB 経由で PC に送信

### 自動テストモード

- 74x163 をフリーラン（連続カウント）モードに設定
- 0 ～ 255 を自動的に順次変換・表示
- 変換精度の検証や、デモンストレーションに有用

## Double-Dabble アルゴリズムの詳細解説

### なぜ+3 なのか？

BCD（2 進化 10 進数）では、各桁は 0 ～ 9 の範囲です。シフト演算により桁上がりが発生する際、通常のバイナリでは 16 進数として処理されてしまいます。

**問題の例:**

```
BCD: 0101 (5) を左シフト → 1010 (10)
→ BCDとして不正（0～9の範囲外）
```

**+3 の効果:**

```
BCD: 0101 (5) に+3 → 1000 (8)
1000を左シフト → 10000
→ 桁上がりが発生し、次の桁に1が伝播
→ 元の桁は0000 (0) に戻る
```

このように、+3 によって次のシフトで正しい桁上がりが発生します。

### 数学的証明（簡易版）

- BCD 桁が 5 以上: 次のシフトで 10 以上になる可能性
- 10 = 1010 (binary) → BCD 2 桁に分割する必要
- 事前に+3 することで、シフト後に正しく桁上がり

詳細な数学的証明は、デジタル回路設計の教科書を参照してください。

## 設計上の考察

### ハードウェア実装 vs ソフトウェア実装

**ハードウェア（本回路）の利点:**

- 並列処理により高速
- 教育的価値が高い（アルゴリズムの可視化）
- マイコン不要

**ハードウェアの欠点:**

- 部品数が多い（IC 約 15 個）
- 配線が複雑
- デバッグが困難

**ソフトウェア（Arduino 等）の利点:**

- 実装が簡単（数行のコード）
- 柔軟な変更が可能
- デバッグが容易

**推奨:**

- 教育・学習目的: ハードウェア実装
- 実用目的: ソフトウェア実装

### 74x85（コンパレータ）を使わない理由

74x85 は未所持のため、論理ゲートで ≧5 判定を実装しました。74x85 を使用する場合:

```
74x85:
  A0～A3 ← BCD桁
  B0～B3 ← "0101" (5の定数)
  A≧B出力 → 判定結果
```

こちらの方がシンプルですが、本プロジェクトでは所持 IC のみで実装することを優先しています。

### 実用的な応用例

- AD コンバータの出力（8 ビットバイナリ）を 10 進数表示
- カウンタ回路の値を 10 進数表示
- マイコンのデバッグ用出力インタフェース
- レトロコンピュータの出力装置
